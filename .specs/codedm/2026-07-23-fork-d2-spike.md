CRITERION 2 — PGlite in `bun build --compile` (PASS, embedding REQUIRED). @electric-sql/pglite 0.5.4. Naive compile FAILS at runtime with `ENOENT: open '/$bunfs/root/pglite.data'` — pglite lazily fetch/reads pglite.wasm + pglite.data + initdb.wasm next to its module, which don't exist inside the single-file binary. FIX (exact recipe): embed the three dist assets with Bun file imports and hand them to the constructor —
import wasmPath from "./node_modules/@electric-sql/pglite/dist/pglite.wasm" with { type: "file" };
import dataPath from "./node_modules/@electric-sql/pglite/dist/pglite.data" with { type: "file" };
import initdbPath from "./node_modules/@electric-sql/pglite/dist/initdb.wasm" with { type: "file" };
then `new PGlite(dataDir, { pgliteWasmModule: await WebAssembly.compile(await Bun.file(wasmPath).arrayBuffer()), initdbWasmModule: await WebAssembly.compile(await Bun.file(initdbPath).arrayBuffer()), fsBundle: new Blob([await Bun.file(dataPath).arrayBuffer()]) })`. (Option names are pgliteWasmModule/initdbWasmModule/fsBundle in 0.5.4 — NOT the older `wasmModule`.) Commands: `bun build --compile main-embed.ts --outfile spike-pglite-embed` (no extra flags needed). Binary run from a DIFFERENT cwd (fresh mktemp dir): CREATE TABLE + INSERT + SELECT OK, file-backed dataDir created relative to cwd with a real PG layout (base/, global/, pg_hba.conf...), and a second run of the binary saw the first run's row (persistence across invocations confirmed). Binary size 81 MB (bun runtime + ~16.7 MB embedded assets). Interpreter mode needs none of this — plain `new PGlite(dataDir)` works under `bun main.ts`.
