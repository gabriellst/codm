# Plan — Channel: rich model canonical + Go schema via sqlc-pull from the contract

**Origin:** founder decision — the channel should be the **rich** clinical-fork model ("não deveríamos ter mudado"), and the Go side should **pull** its schema from the Drizzle contract (single migration owner) via **sqlc reading the contract migration files**, not hand-maintain a parallel golang-migrate set.

**Root cause being fixed:** two schema owners diverged. The contract (Drizzle) migrated `gateway.channels` LEAN (`kind, account_detail`); the Go gateway (verbatim clinical-fork port) queries the RICH shape (`platform, name, owner_remote_id, credentials, version`) via hand-written SQL. Column-not-exist → 500 on every channel call. (Diagnosed live 2026-07-23 while spinning up the desktop app.)

**Grounding:** see the map in the investigation subagent output (2026-07-23). Highlights baked in below.

---

## What the map changed vs the first sketch
- **Only `channels` diverges.** `remotes`/`messages`/`remote_memberships` (contract `0006`) already match the Go rich repos column-for-column. No change to those tables.
- **Enums are the real reconcile** (value-sets, not renames): `platform` needs `INTERNAL` (used by `message_projector.go`), `status` needs the 5-value set (soft-delete `DELETED` + active-filter `CONNECTING`), `remotes.type` writes `USER` not `CONTACT`.
- **sqlc buys models, not most queries.** The dynamic/batch SQL (`List`, `ListByRemote`, chunked upserts, `RewriteRemoteIDs`, `BulkUpdateMemberships`) stays hand-written. sqlc's payoff = generated column-structs = a **compile-time drift guard** (would have caught this bug).
- **Go golang-migrate set is orphaned** — `cmd/api` never runs it (grep-verified: only `cmd/migrate/main.go` + the Go test harness use `RunMigrations`/`MigrationsFS`). Deleting it only forces re-pointing the Go test harness to the contract schema.

## Target state
**`gateway.channels` (rich):** `id uuid PK`, `owner_id text`, `platform text`, `name text`, `owner_remote_id text default ''`, `credentials jsonb default '{}'`, `status text`, `created_at tz`, `updated_at tz`, `version bigint default 0`. Indexes `idx_channels_owner_id`, `idx_channels_owner_platform(owner_id, platform)`. (Drop dead `connected_at`/`disconnected_at`; the lean `kind`→`platform`, `account_detail`→`owner_remote_id`.)

**Contract enums reconciled to the rich value-sets** (source: `packages/contracts/wire/enums/*.tsp` → regen ts+go wire):
- `ChannelKind`→**`Platform`**: `WHATSAPP, INTERNAL` (drop the speculative INSTAGRAM_DM/TELEGRAM unless kept intentionally).
- `ChannelStatus`: `CREATED, CONNECTING, CONNECTED, DISCONNECTED, DELETED`.
- `ContactKind`→**`RemoteType`**: `USER, GROUP, BROADCAST`.
- `Direction`: already unified — no change.
Go domain enums (`internal/channel/enums/*`) then **alias the contract wire enums** rather than redeclare (kills the divergence permanently).

**Single schema source = Drizzle.** Go golang-migrate `core/db/sql/migrations` deleted; Go models generated by sqlc from the contract schema; Go test harness builds its schema from the contract (snapshot), not `MigrationsFS`.

## owner_id type — DECISION: `text`
Go migration/repo use `owner_id TEXT` (scans into Go `string`, inserts string; tests use non-uuid `'integration-tenant'`). Contract lean used `uuid`. Rich model is authoritative → **`text`** (uuid values fit; keeps Go tests green). Minor divergence from the uuid convention elsewhere — accepted, noted.

## Phase 2 — Go conforms to contract + sqlc pull + delete orphaned Go migrations (HARDENING + UNBLOCK)
Delivers: single schema source + compile-time drift guard; the bug class can't recur — AND unblocks the resolve (Phase 1 alone doesn't).

**Live-discovered divergence (2026-07-24, blocking):** Phase 1 unblocked the channel query, but the resolve then failed on the SHARED event-sourcing layer — the Go `core-go` `PgDomainEventRepository` (core/repositories/pg_domain_event_repository.go) writes `INSERT INTO shared.events (id,name,entity_id,owner_id,payload,time,updated_at)` and `shared.outbox (id,name,source,owner_id,payload,time,created_at,updated_at)`, but the contract (infrastructure.ts) has `shared.events(id,name,entity_id,owner_id,payload,source,occurred_at)` and `shared.outbox(id,name,entity_id,owner_id,payload,source,processed_at,attempts,last_error,created_at)`. So the Go writes non-existent `time`/`updated_at` and omits `source`/`entity_id`. Blocks EVERY Go command that raises a domain event.

**Direction (founder-confirmed): for SHARED infra the Go conforms to the CONTRACT** (`occurred_at`/`source`, drop `time`/`updated_at`) — the OPPOSITE of the channel model (contract went rich to match Go). `infrastructure.ts` is the deliberate shared shape used by TS + Go.

**Discovery-first (avoid whack-a-mole):** step 5.0 produces the FULL Go-hand-written-SQL ↔ contract column diff across ALL shared + gateway tables (shared.events, shared.outbox + its dispatcher READ/UPDATE + mark-processed, gateway.channels/remotes/messages/remote_memberships) so every divergence is fixed in one pass. sqlc generates the MODELS (drift-guard on SELECT scans); the hand-written SQL column-name literals are reconciled manually to the contract.

5.0 **Audit**: full Go-SQL ↔ contract column diff (all tables above) → the reconcile work-list.
5.1 **Reconcile Go SQL to the contract**: fix column names in pg_domain_event_repository.go (events/outbox insert), the outbox dispatcher read/update/mark-processed, and any remaining gateway repo drift — to the contract columns. core/types/events.go json tags stay (wire shape ≠ DB columns).
6. **sqlc config** (`packages/api/go/sqlc.yaml`): schema source = **option A** (contract `packages/contracts/db/migrations` with a `--> statement-breakpoint` strip) — **spike-gated**: if sqlc's parser chokes on multi-schema/`CREATE SCHEMA`/qualified idents, fall back to **option B** (migrate a throwaway DB, `pg_dump --schema-only` the `gateway` schema → committed `schema.sql` → sqlc). Generate models into e.g. `internal/channel/db/`; enum columns overridden onto `template/contracts-go/wire`.
7. **Repos adopt generated structs** (map §5): fixed-shape queries can use sqlc; dynamic/batch stay hand-written but over the generated structs (so a schema change breaks the build).
8. **Delete** `packages/api/go/core/db/sql/migrations` (+ 18 down); remove/repoint `cmd/migrate` + `migrate.go`/`embedded.go`; **keep** `client.go`/`WithSearchPath` (still targets the `gateway` search_path).
9. **Re-point Go test harness** (`embedded_test.go`, `testmain_test.go`, `testdb_test.go`) to build the schema from the contract (snapshot), not `MigrationsFS()`.
- Gates: go build+test (harness reschemed) · sqlc generate idempotent · api-ts unaffected · resolve 200 still green · full battery (tsc/apitest/goapi/gocore/astro/tooling/sdk/e2e).
