## RSS de regime do daemon TS COM PGlite (o número de comparação do aceite, T31)

Procedimento: `bun run src/index.ts` com `CODEDM_DATA_DIR` num dir temporário e `API_PORT=3098`;
espera `GET /v1/session` responder 200; **30s** de regime; três leituras de
`ps -o rss= -p <pid>` com **10s** de intervalo; mediana.

```
READY_AFTER_S=2
RSS_SAMPLES_KB=340336,337712,336608
RSS_MEDIAN_KB=337712
DATA_DIR_KB=28256
```

- `RSS_MEDIAN_KB=337712` (~330 MiB) — daemon TS + PGlite embarcado, em regime.
- `DATA_DIR_KB=28256` (~27.6 MiB) — `du -sk` do data dir PGlite recém-migrado, sem carga.

Shutdown limpo observado no mesmo run (`HTTP server stopped` → `OutboxDispatcher stopped` →
`Database connections closed`), ou seja o número é de um processo saudável, não de um que morreu
no meio.

## Notas de leitura

- O RSS acima é o **teto a bater**: a decisão (a) troca PGlite (WASM + heap do Postgres embarcado)
  por `@libsql/client` (addon nativo). Uma regressão de RSS depois do flip é sinal de que algo
  ficou carregado à toa, não de ruído de medição — as três amostras variam <1.2%.
- `DATA_DIR_KB` mede o **substrato antigo**. Depois do flip o data dir passa a ser o mesmo
  `codedm.db` do gateway Go, e a comparação relevante deixa de ser dir-vs-dir e vira
  arquivo-vs-dir. Registrado aqui só para que a comparação seja possível.
